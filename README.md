## Про репозиторій

Цей репозиторій містить результати виконання лабораторних робіт з дисципліни **«Об'єктно-орієнтоване програмування»**.

Мета робіт — закріпити принципи ООП та отримати практичний досвід розробки програмного забезпечення: від проєктування класів і написання модульних тестів до обробки структурованих даних та створення Android-застосунків.

Кожна лабораторна робота розміщена в окремій директорії та має власну документацію з описом завдання, використаних технологій і способу запуску.

##  Лабораторна робота №1 — Railway Transport

**Тема:** ієрархія рухомого складу залізничного транспорту.

Навчальна програма моделює пасажирський поїзд, його локомотиви та пасажирські вагони. Проєкт демонструє використання основних принципів об'єктно-орієнтованого програмування.

### Реалізовано

- Ієрархію класів на основі абстрактного базового класу.
- Наслідування та перевизначення методів.
- Композицію для формування пасажирського поїзда.
- Підрахунок загальної кількості пасажирів і багажу.
- Сортування вагонів за рівнем комфортності.
- Пошук вагонів за заданим діапазоном місткості.
- Модульні тести з використанням JUnit 5 та Mockito.

**Технології:** Java 17, Maven, JUnit 5, Mockito.

##  Лабораторна робота №2 — MilitaryPlanesXML

**Варіант:** №8.

**Тема:** робота з XML-документами та технологіями їх обробки.

Проєкт призначений для зберігання й обробки інформації про військові літаки. Основна увага приділена структуруванню XML-даних, перевірці їх коректності та використанню різних підходів до парсингу.

### Реалізовано

- XML-документ з інформацією про військові літаки.
- XSD-схему з типами даних, обмеженнями та атрибутами.
- Валідацію XML-документа за XSD.
- Обробку документів трьома способами: SAX, DOM та StAX.
- Спільну Java-модель для представлення літаків.
- Сортування об'єктів за допомогою Comparator.
- XSLT-перетворення з групуванням за країною походження.
- Перевірку додаткових бізнес-правил у Java.
- Модульні тести з JUnit 5.

**Технології:** Java 17, Maven, XML, XSD, SAX, DOM, StAX, XSLT, JUnit 5.

##  Лабораторна робота №3 — SirovarWeather

**Тема:** розробка Android-застосунку для перегляду прогнозу погоди.

SirovarWeather — мобільний застосунок, який отримує актуальні погодні дані через Open-Meteo API та надає користувачу зручний інтерфейс для перегляду прогнозу.

Застосунок написаний на **Java**, а інтерфейс побудований за допомогою Android Views та XML.

### Реалізовано

- Відображення поточної погоди та основних метеопоказників.
- Погодинний прогноз на наступні 24 години.
- Прогноз погоди на 7 днів.
- Пошук міст через Open-Meteo Geocoding API.
- Збереження вибраного міста та налаштувань.
- Кешування останніх погодних даних для доступу офлайн.
- Компактний та розширений Android App Widget.
- Фонове оновлення даних за допомогою WorkManager.
- Вибір одиниць вимірювання температури та швидкості вітру.
- Українська та англійська локалізації.
- Світла й темна теми оформлення.
- Логування подій за допомогою Timber.
- Модульні та Android-тести.

### Використані технології

| Компонент | Технологія |
|---|---|
| Мова програмування | Java |
| Платформа | Android SDK |
| Інтерфейс | Android Views, XML, Material Components |
| Мережеві запити | Retrofit, OkHttp |
| Обробка JSON | Gson |
| Локальне збереження | SharedPreferences |
| Фонові завдання | WorkManager |
| Логування | Timber |
| Тестування | JUnit 4, AndroidX Test |
| Джерело погоди | Open-Meteo API |

**API не потребує ключа доступу.**

##  Вимоги до середовища

Для роботи з проєктами знадобляться:

- **JDK 17 або новіший** — для лабораторних №1 та №2.
- **Apache Maven 3.8+** — для складання Java-проєктів.
- **Android Studio** — для роботи з лабораторною №3.
- **Android SDK Platform 35** — для складання SirovarWeather.
- **JDK 17** — для Gradle та Android Gradle Plugin.

> Лабораторні роботи є окремими проєктами. Для кожної з них використовується власна система складання та інструкція запуску.

##  Початок роботи

Клонуйте репозиторій:

```bash
git clone https://github.com/Danil2006050406/3_course_lab_OOP.git
```

Перейдіть до потрібної лабораторної:

```bash
cd 3_course_lab_OOP
```

### Запуск Lab1

```bash
cd Lab1
mvn clean test
mvn compile
```

### Запуск Lab2

```bash
cd Lab2
mvn test
mvn package
```

### Запуск Lab3

Відкрийте директорію `Lab3` в Android Studio, дочекайтеся синхронізації Gradle та запустіть конфігурацію `app`.

У Windows також можна зібрати APK з командного рядка:

```powershell
cd Lab3
.\gradlew.bat assembleDebug
```

Детальні інструкції, включно з тестуванням, наведені в README відповідної лабораторної.

##  Тестування

У проєктах використовуються автоматизовані тести для перевірки коректності реалізації:

- **Lab1:** JUnit 5 та Mockito — перевірка моделей і бізнес-логіки.

Команди запуску тестів наведені в документації кожного проєкту.
